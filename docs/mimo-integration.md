# MiMo V2.5-Pro 集成实践

## 模型概述

小米 MiMo V2.5-Pro 是小米自研的推理型大语言模型，在数学推理和代码生成方面表现突出，同时具备良好的中文理解和通用对话能力。本文档记录将其作为 AI Agent 系统主模型的实际使用经验。

## 基本参数

| 参数 | 值 |
|------|-----|
| 上下文窗口 | 262,144 tokens |
| 定价（输入） | ¥0.001 / 1K tokens |
| 定价（输出） | ¥0.005 / 1K tokens |
| Provider | xiaomi（通过 OpenAI 兼容接口） |
| API 端点 | `https://api.xiaomimimo.com/v1` |

## 与 Hermes Agent 集成

Hermes Agent 原生支持 OpenAI 兼容 API，MiMo 可直接作为 provider 配置：

```yaml
providers:
  xiaomi:
    base_url: "https://api.xiaomimimo.com/v1"
    api_key_env: "XIAOMI_API_KEY"
    default_model: "mimo-v2.5-pro"
```

## Token 消耗模式

作为 Agentic 工作流的主模型，MiMo 的 Token 消耗有以下特点：

### 单会话消耗
- 简单问答：5,000~20,000 tokens
- 代码审查任务：50,000~200,000 tokens
- 复杂研究报告：200,000~800,000 tokens
- 多 Agent 委派任务：500,000~2,000,000 tokens

### 日均消耗
- 低活跃日：500~1,000 万 tokens
- 正常工作日：1,000~3,000 万 tokens
- 高强度开发日：3,000~5,000 万 tokens

### 缓存命中率
MiMo 支持上下文缓存，实际使用中缓存命中率可达 **97% 以上**，大幅降低了重复上下文的成本。

## 推荐使用场景

1. **日常对话和问答** — MiMo 响应快、成本低
2. **代码编写和审查** — MiMo 代码能力强
3. **长文档处理** — 262K 上下文窗口支持大文档
4. **多轮工具调用** — Agent 工具调用稳定可靠

## 已知限制

1. **API 稳定性**：偶尔会出现较长的首 token 延迟
2. **并发限制**：高频并发请求可能触发限流
3. **Token 计数差异**：面板统计与官方控制台可能存在 2~3 倍差距（因其他工具共用 API Key）

## 优化建议

1. **利用缓存**：保持系统提示和常用上下文稳定，最大化缓存命中率
2. **合理使用子代理**：将简单辅助任务分配给更便宜的模型（如 DeepSeek Flash）
3. **控制上下文长度**：定期清理不必要的历史消息
4. **设置 fallback**：配置自动降级策略，MiMo 不可用时切换到 DeepSeek

## 成本估算

按照日均 2,000 万 tokens（缓存后实际计费约 60 万 tokens）计算：
- 日均成本：约 ¥0.4~0.8
- 月均成本：约 ¥12~24

这使得 MiMo 成为目前性价比最高的 Agent 主模型选择之一。
